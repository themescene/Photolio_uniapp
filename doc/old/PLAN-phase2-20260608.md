## 关键决策（沿用进 Phase 3）

| 决策 | 选择 | 原因 |
|---|---|---|
| 项目本质 | **迁移**网页端到 uniapp，**不是**重新设计 | 用户多次强调，违反代价高 |
| 写代码前 | **先读 [annualreport/src/](../../../demo/annualreport/src/) 对应 Vue** | README 铁律 |
| 单元名 | **「画匣子」**（既是品牌名也是单元名），全 UI 禁出现「片语」 | 用户决策 2026-06-08 |
| AI 字眼 | **全 UI 禁出现**，用「编织」/「生成」等中性词；法律文本里「不用于 AI 训练」例外保留 | 用户决策 2026-06-08 |
| 主题色 | **中性白 / 深灰**（网页端 base.css）；暖木 / 黄铜仅 wooden_box 模板内使用 | 网页端事实 |
| 主页底栏 | 5 tab：画匣子 / 上传 / 播放 / NFC / 我的（其中"播放"目前是占位 + 最近播放回放） | 用户指定 2026-06-08 |
| 创作模式 | 单轮多图，9 张上限；第 1 张走 analyze-image，其余走 upload-image（省 AI 等待） | Phase 2 性能优化 |
| NFC 绑定 | 任何登录用户拿到 UID 都能绑（持卡=授权） | 用户决策 |
| 兑换码 | `photolio2026` → `preset_links`（toB 商家功能），框架以后可扩 VIP 等 | 用户决策 |
| URL Link 端到端 | 受微信 errcode 85079 阻塞，需小程序发布版本，移交 Phase 3 | 微信平台限制 |
| 模板移植策略 | **直接搬运网页端结构**（image-section aspect 8/7 + tray + photo-stack-wrap 78% + polaroid absolute inset 0），不自己设计 | Phase 2 第一版自己造轮子被用户驳回 |

## 走过的弯路（教训写进 README）

1. 第一版 BrandHeader 漏了 isTyping flag，光标一直 blink → 整段闪。**根因**：没读 PageHeader.vue 网页端原版
2. 第一版 ShareGrid 用了正方形 + 4 档渐变 + 创意性 hover scale → 跟网页端不一致。**根因**：没读 CollectionCard.vue
3. 第一版 WoodenBoxCard 用 flex 布局取代 absolute 嵌套 → 图片消失。**根因**：没读 WoodenBoxCard.vue 网页端结构
4. 第一版 ShareGrid 事件名 `tap` → 被小程序原生 tap 事件吞掉 → openShare 拿到 undefined → `/api/share/undefined` 404。**根因**：不知道 mp-weixin 保留事件名
5. tabBar 配置改了后没全量重新编译 → DevTools 显示 `pages/xxx/index.wxml` 字面量。**根因**：以为热重载够用
6. 创作页底部按钮被 textarea 撑高顶出屏外。**根因**：用了 `margin-top: auto + min-height: 100vh` 而不是固定操作栏
7. 词汇没统一 → UI 里到处都是「片语」「AI 编织」。**根因**：用户喊停才意识到要全局清洗

**结论**：迁移任务，**先读 Vue 再写 uniapp** 是铁律，违反就走样。
