## Phase 1 目标

在微信小程序里跑出**可演示的最小闭环**：

1. **脚手架可跑**：`npm run dev:mp-weixin` 能在微信开发者工具里展示首屏，`npm run dev:h5` 能在浏览器跑同一份代码
2. **NFC 入口骨架**：
   - `App.vue.onLaunch(options)` 从 `query.q` / `query.uid` 拿到 14 位 hex UID
   - redirect 到 `/pages/nfc/landing?uid=<uid>`
   - landing 页调后端 `/api/nfc/<uid>`：
     - `status=empty` → 渲染"待绑定"占位（实际绑定流程归 Phase 2）
     - `status=filled` + `bound_type=nfc`（视频/音频/文件直链）→ 跳到对应播放页
     - `status=filled` + `bound_type=share`（图文画匣子）→ 跳到 `/pages/share/play?id=<id>`
3. **登录注册**：沿用后端 `/api/auth/register` / `/api/auth/login`，token 存 `uni.setStorageSync`
4. **主页**：登录态下拉 `/api/user/shares` 渲染片语卡片列表（缩略图 + 标题 + 创建时间）

**不在 Phase 1 范围**（明确推迟）：
- 片语创作（拍照、录音、AI 分析、generate-report）
- 播放器 10 种模板（Phase 2 只先做 `wooden_box`）
- 群组协同 / 合并报告 / 春联
- `html-to-image` 等价的 canvas 分享图
- iOS / Android 原生包打包
- IndexedDB 缩略图缓存（先走网络）

## 关键决策记录

| 决策 | 选择 | 原因 |
|---|---|---|
| 脚手架路线 | uniapp CLI + Vite + TS（`degit dcloudio/uni-preset-vue#vite-ts`） | 多 IDE 协作（VS Code / Cursor），编译器在项目内不依赖 HBuilderX |
| 主目标平台 | mp-weixin（H5 兼顾） | 商业目标是覆盖鸿蒙等无法走 Web NFC 的设备 |
| NFC 必须保留 | 是 | 本次迁移核心商业价值，不能砍 |
| NFC 卡 URL 策略 | 烧 `https://pian-yu.com/n/<14位UID占位>`（NXP UID Mirroring 保留）→ 服务器 UA 分流 → 微信内直跳小程序 / 微信外用 URL Link | 既保留批量烧卡能力，又解决 URL Link 30 天过期问题 |
| 账号体系 | 微信主登 + 用户名/密码旁路 + 旧账号绑定（一对一，绑定后联合查询不迁移数据） | 用户决策，2026-06-08 |
| 首登默认昵称 | `匣子_XXXX`（4 位 hex） | 用户决策（拉不到微信公开昵称） |
| H5 微信登录 | 暂不做（H5 走旧用户名/密码） | 用户决策 |
| 旧账号密码传输 | 明文 over HTTPS | 用户决策 |
| 后端 | 不动接口契约，新增端点 | 减小本阶段变量 |
| 文档规约 | 两文档制（README + doc/PLAN.md + doc/old/） | 用户指定 |
